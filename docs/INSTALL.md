# 安装、授权与已知问题

**Harmony Remote 0.6.0 开发预览版** · 发布标签 `v0.6.0-preview.1` · Host build **1000013** / Mac build **9**

下载入口：[GitHub Release](https://github.com/longxinzhang/harmony-remote-desktop/releases/tag/v0.6.0-preview.1)。本版面向愿意反馈问题的早期体验者，适用于同一可信局域网中的 **Apple Silicon Mac → HarmonyOS PC**。

## 选择下载包

| 下载内容 | 适用设备 | 拿到后如何使用 |
| --- | --- | --- |
| `HarmonyRemote-0.6.0-macOS-arm64.zip` | Apple Silicon（M 系列芯片），macOS 14 或更新版本 | 解压得到 `HarmonyRemote.app`，移到“应用程序”后打开；首次运行可能需要按下文处理系统提示 |
| `HarmonyRemote-0.6.0-HarmonyOS-arm64-unsigned.hap` | HarmonyOS PC / `2in1`，arm64，API 26 | **未签名的开发者产物，不能直接安装**；需要使用自己的开发者账号、设备及含所需 ACL 的 Profile 签名。推荐按[源码构建步骤](https://github.com/longxinzhang/harmony-remote-desktop/blob/main/docs/BUILDING.md)操作 |
| `SHA256SUMS` | 两个平台 | 用于核对下载文件完整性；文件名与校验值以该次 Release 为准 |
| `release-manifest.json`、`INSTALL.md`、`RELEASE_NOTES.md` | 两个平台 | 查看构建来源、产物信息、安装说明及本版变更 |

Mac 包当前采用 **ad-hoc 签名，未经过 Apple Developer ID 签名与公证**。Harmony 包没有可供任意设备安装的正式分发签名。公开发布这些文件，并不意味着两端都已经实现“下载即安装”。

本次不会公开开发设备专用的已签名 HAP。该包使用绑定指定设备的 debug Profile，不能充当通用安装包；个人签名材料和完整 Profile 也不随 Release 发布。Harmony 安装条件参见[华为调试 Profile 说明](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/agc-help-debug-profile-0000002248181278)。

## Mac：解压与首次打开

1. 从本仓库 Release 下载 Mac ZIP，解压，将 `HarmonyRemote.app` 移到“应用程序”。无需另外安装 ffmpeg 或开发工具。只保留一个常用安装位置，便于后续更新和登录启动。
2. 双击打开。由于本版未公证，macOS 可能提示无法验证开发者或无法检查恶意软件。
3. 核对下载来源及校验值后，如果确定要体验此预览版，可在尝试打开之后，前往 **系统设置 → 隐私与安全性 → 仍要打开**，再确认打开。具体提示及受管理设备的限制见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。不要关闭系统全局安全检查。

若系统明确提示应用已损坏、将损坏电脑，或校验值不符，先停止打开、重新核对下载；不要把所有安全提示都当作普通的“未公证”提示。

Mac 作为控制端，不需要获取本机屏幕录制、麦克风或辅助功能权限。系统可能按功能询问以下许可：

| 许可或系统提示 | 用途 | 拒绝或不开启的影响 |
| --- | --- | --- |
| 本地网络 | 连接同一局域网的鸿蒙 PC | 可能无法建立连接；出现提示时按需允许 |
| 剪贴板访问 | 将 Mac 新复制的文字同步到鸿蒙 | Mac → 鸿蒙的文字同步可能不可用；画面与键鼠控制可单独使用 |
| 钥匙串访问 | 选择记住设备后保存、读取配对身份 | 可能无法保存或恢复持久配对；应用更新或移动后可能再次询问 |
| 登录项 | 用户显式开启“登录 Mac 后启动” | 不会随登录自动打开；手动启动不受影响 |

不同 macOS 版本的提示方式可能不同。未出现弹窗不等于功能失败，以应用显示状态与实际连接结果为准。

## Harmony：安装条件

当前 Host 面向 **HarmonyOS PC / API 26**，不适用于旧版鸿蒙、手机或平板。开发构建使用 SDK **26.0.0.105**；不能仅凭系统市场版本号相近就认定兼容。

推荐先按[构建与安装](https://github.com/longxinzhang/harmony-remote-desktop/blob/main/docs/BUILDING.md)配置 DevEco、连接自己的鸿蒙 PC，并生成覆盖自己设备的签名。文字剪贴板需要在签名 Profile 中取得 `READ_PASTEBOARD` ACL；仅在应用清单里写入权限名称不够。修改权限后应重新生成相应 Profile 并构建，不要沿用缺少 ACL 或不包含当前设备的旧签名。

Release 中的 unsigned HAP 供开发者使用。它不包含可用于绕过设备绑定、ACL 审批或系统授权的签名；没有开发签名环境的普通用户，目前仍需等待后续正式分发版本。

## 鸿蒙端每项授权是什么意思

应用清单目前只声明 **`ohos.permission.INTERNET`** 与 **`ohos.permission.READ_PASTEBOARD`**。屏幕共享和键鼠控制另走系统提供的用户确认流程；它们不是“安装完成就永久允许”。

| 权限 / 开关 | 为什么需要、何时开启 | 不允许会怎样 | 如何停止 |
| --- | --- | --- | --- |
| 网络 `ohos.permission.INTERNET` | 建立局域网连接，传送桌面、输入事件及按需开启的剪贴板、声音。本机 SDK 将其列为系统授予权限，一般没有独立运行时弹窗 | 无法进行远程连接 | 点击“下线并断开连接”或退出应用 |
| 系统屏幕共享确认 | 在鸿蒙点击“开始共享屏幕”后，由系统确认本次共享范围；把所选屏幕画面发送到 Mac | Mac 无法看到桌面；配对成功不会替你同意共享 | 点击“停止共享”，或使用系统的停止共享入口 |
| 系统键鼠授权 | 点击“授权键鼠权限”，通过 `OH_Input_RequestInjection` 请求系统允许输入注入 | 仍可查看已授权的共享画面，但不能远程操作 | 设置页点击“释放按键并撤销授权”；服务下线也会撤销本次输入授权 |
| “允许远程控制” | 在系统授权之外，再允许当前会话接收操作；Mac 还需开启控制并点击画面获得焦点 | 保持仅查看 | 鸿蒙点击“关闭远程控制”，或 Mac 关闭控制；应用会清理待执行输入并尝试释放持有的按键 |
| 剪贴板读取 `ohos.permission.READ_PASTEBOARD` | 点击“允许读取剪贴板”后申请读取系统剪贴板，以便把鸿蒙新复制的纯文字发送到 Mac；还需要签名中的 ACL | 鸿蒙 → Mac 不可用；Mac → 鸿蒙接收可单独尝试 | 关闭剪贴板同步；若需撤销系统读取许可，在系统应用权限中管理 |
| “允许剪贴板同步”与 Mac 方向选择 | 鸿蒙允许同步后，在 Mac 选择关闭、Mac → 鸿蒙、鸿蒙 → Mac 或双向 | 不跨设备同步；不影响画面与普通键鼠控制 | 在任一端关闭同步；关闭或断线会取消待处理的同步与粘贴任务 |
| “共享系统声音” | 默认关闭；在设置中开启后，下次共享时随屏幕共享一起请求系统确认 | 画面与控制仍可用，Mac 听不到鸿蒙系统播放的声音 | 停止共享；下一次开始前关闭声音选项，或在 Mac 静音 |

**剪贴板没有再次弹窗也可能是正常情况**：系统已有授权时，以页面“读取权限：已允许”和实际新复制文字的结果为准。若显示未允许或授权失败，应检查系统应用权限及签名 ACL，不要反复点击或把旧剪贴板能粘贴当作同步成功。

本版不申请 `CONTROL_DEVICE` 系统设备控制权限，不采集麦克风，不申请相机权限，也不要求辅助功能服务。系统声音是设备正在播放的声音，**不是麦克风录音**。当前没有文件传输功能，因此不需要为此提供任意文件读写授权。

“永久上线”仅表示共享不设自动结束时间；不表示无人值守授权、绕过锁屏或保证重启后自动恢复控制。持久配对也只保存设备身份，不替代屏幕、键鼠和剪贴板授权。

## 第一次连接

1. 两台电脑接入同一可信局域网。鸿蒙打开 Harmony Remote，点击 **开启服务**，查看本机地址与六位连接码。
2. 在 Mac 输入该地址与连接码。连接码显示时的有效期为 5 分钟，且只能使用一次。需要记住设备时，在鸿蒙设置允许新增可信设备，并在 Mac 勾选记住设备。
3. 鸿蒙点击 **开始共享屏幕**，按系统弹窗确认。等 Mac 出现实际桌面后，再测试后续功能。
4. 需要操作时，鸿蒙 **授权键鼠权限 → 允许远程控制**，Mac **启用键鼠控制 → 点击远程画面**。Mac 的 `⌘⇧Esc` 可释放画面输入焦点。
5. 需要文字同步时，鸿蒙 **允许读取剪贴板 → 允许剪贴板同步**，Mac 选择同步方向，然后重新复制一段非敏感测试文字。开启或重连不会自动交换此前的剪贴板。

只想看画面时，可不启用控制、剪贴板或声音。遇到操作异常，先关闭相应功能；鸿蒙 **下线并断开连接** 会停止共享、关闭会话和剪贴板同步，并撤销本次输入授权。

当前连接是**未加密的局域网传输**。请只在可信局域网使用，不要将服务端口直接暴露到公网；“已配对”表示设备身份校验，不表示画面、按键、声音或剪贴板已加密。

## 已知问题与限制

| 问题 / 限制 | 当前表现及建议 |
| --- | --- |
| 密码输入区域可能变黑 | 当前默认窗口级遮挡。AionUI 网页已确认：聚焦密码框时网页被遮挡，网页外桌面正常，点击其他区域后恢复。系统保护的是窗口区域，不能承诺只遮住密码输入框；其他应用及系统认证弹窗尚未验收 |
| 部分应用的文字复制兼容性 | 曾出现通过远程操作鸿蒙备忘录复制后仍粘贴旧内容；同步时序修复已加入，但完整真机回归仍待完成。遇到此问题先关闭同步，并用新的非敏感文字对照测试，避免误粘贴 |
| 仅支持纯文字剪贴板 | 单次最多 1 MiB UTF-8，不保留排版；文件、图片及部分富文本格式不支持。文件传输、文件复制粘贴尚未实现 |
| 60 FPS 是目标上限 | 停止共享后切换，下次开始生效；实际帧率取决于硬件、桌面变化和网络。静止画面帧率较低不一定是故障 |
| 系统声音为预览能力 | 仅鸿蒙 → Mac，可能受目标应用和系统隐私限制；当前没有基于两端时钟校准的声画同步，不能承诺所有应用都能传声 |
| 断线恢复有条件 | 已认证的同一设备可在原采集的有限保留期内尝试恢复，保留期最多 60 秒；主动停止、权限撤销、过期或采集终止后需要重新共享。旧按键和待粘贴不会重放，控制不会自动启用 |
| 开机与登录启动能力不同 | Mac 支持用户开启登录后启动；鸿蒙只读取系统自启动状态，可设置“打开应用后启动服务”。不能在应用内替用户打开鸿蒙系统开机自启 |
| 平台及发布范围有限 | 当前为 Apple Silicon Mac 控制 HarmonyOS PC，可信局域网直连；Intel Mac、Windows、Linux、手机、网页控制端及公网中继尚未发布 |

## 哪些已经验证，哪些仍在验证

**已有真机结果**：局域网桌面查看、英文输入、右键、常用快捷键、窗口拖动、文字拖选；已有完整五分钟共享及更长会话使用记录。当前两个构建已在开发设备上运行；AionUI 窗口遮挡与退出后的恢复已由用户确认。

**已实现但还需完整真机验收**：60 FPS 动态画面、系统声音实际播放与长时间声画偏差、真实断网重连、配对跨应用/系统重启、系统登录启动、备忘录复制兼容性、完整快捷键及持键断网释放矩阵。自动化和回环测试通过不等于这些场景全部通过。

**长期资源使用**：累计解码十万帧表示处理过的数量，不表示把十万张图片留在内存。实现对解码任务、待显示帧和诊断历史设有边界；已有短时资源采样及峰值回落记录，但尚未完成 8～24 小时持续稳定性验收。

最新功能矩阵见[首页当前进展](https://github.com/longxinzhang/harmony-remote-desktop#progress)。历史验收文档保留各自构建当时的结果，不能把旧版全部自动视为本版已复测。

## 诊断与反馈

遇到问题时，可在 Mac **开发测试 → 导出诊断** 保存计数与状态，并在 [GitHub Issues](https://github.com/longxinzhang/harmony-remote-desktop/issues) 提供两端版本、系统版本、操作步骤、预期结果与实际结果。Mac 进入开发测试页会暂停隐藏画面的显示提交，但接收与解码可继续；不要把这一差异直接当作黑屏故障。

正常局域网共享不保存桌面录像。诊断设计为记录状态、数量、时间与错误码，不包含画面、密码、输入文字、配对码或剪贴板正文。开发测试中的独立本地编码探针会产生测试视频，排查敏感场景时不要使用该入口。

提交反馈前检查附件，不上传真实密码、连接码、签名材料、完整 Profile、私人剪贴板内容或敏感截图。描述密码框问题只需提供应用名称、遮挡范围及退出后是否恢复。
