## 回来后按顺序复测

1. **更新两端并确认身份能力**：解锁 Mac，恢复鸿蒙无线调试后安装本候选。在鸿蒙开发测试页确认配对密钥“可用”；若不可用，保存诊断，以 `pairingError` 定位 HUKS 初始化阶段。不要把旧 PIN 兼容连接当成持久配对成功。
2. **持久配对**：鸿蒙设置中打开“允许新增可信设备”，开启服务；Mac 勾选“记住这台设备”并用新 PIN 连接。配对完成后退出并重开两端，启动 Host 服务，用 Mac“已配对设备”连接，不输入 PIN。再测试 Host 撤销后旧记录不能恢复。Mac 钥匙串若询问访问许可，由用户核对并处理。
3. **短暂断线**：先由鸿蒙本机开始并允许共享，Mac 启用自动重连。短暂断开 Mac 网络后恢复，在 Host 检测断线后的 60 秒保留期内应恢复图像，键鼠控制保持关闭、旧按键和待粘贴不重放。另测超过保留期、主动停止、撤销权限；这些情况下不能自动恢复采集，需重新开始共享。
4. **帧率与声音**：先用 30 FPS；停止共享后选 60 FPS 并打开系统声音，再开始共享并允许。持续拖动窗口或播放测试视频，观察接收 FPS、实际听到的声音、Mac 静音以及停止后的静音状态。选择 60 只表示目标上限，应记录硬件接受结果与动态画面实测。音频当前为 Harmony → Mac 系统声音，不采麦克风。
5. **网络统计**：连接后观察网络类型、RTT、抖动、视频 Mbps 和接收 FPS；断开后应显示断开，重连后重新采样。RTT 是网络往返时间，不是完整远程交互延迟。
6. **启动**：在 Mac 设置中显式打开“登录 Mac 后启动”，核对系统状态，再由用户选择方便的时间注销/登录验证。鸿蒙先读取系统自启动状态；普通应用没有公开开启接口，不能保证开机自启。单独验证“打开应用后自动开启服务”的记忆与监听行为。启动不得自动打开录屏、输入或剪贴板授权。
7. **继承功能回归**：保留此前 Notes 剪贴板修复待复测项，使用非敏感测试文字验证终端、备忘录双向复制、断线时待粘贴取消，以及拖拽/拖选。持续共享后再记录 CPU、内存与声音偏差。

每组完成后在 Host 开发测试页保存当前诊断，Mac 导出诊断。`collect-lan.py` 已支持 0.6.0 的音频快照并拒绝凭据/音频内容字段；导出成功只证明取得诊断，不自动判定功能通过。
