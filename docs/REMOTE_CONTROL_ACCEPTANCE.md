## 连接与授权

1. 鸿蒙端打开已安装的 **0.5.0**，点击 **Start Server**。“在线，等待连接”是 `LISTENING` 的界面中文，协议/诊断枚举未变。
2. 点击 **Request Input Permission** 并允许系统授权，状态应为 `AUTHORIZED`；点击 **允许远程控制**。也可以保持仅查看。
3. Mac 打开已同步为 **0.5.0** 的 `client-macos/build/HarmonyRemote.app`，输入 Host 页面 IP 和新的一次性 PIN，点击 **连接**。部署指纹见本版构建记录。0.4.1 已验收二进制仍保留于 `artifacts/releases/0.4.1/mac-build/HarmonyRemote.app`；[历史 Mac ZIP](../artifacts/releases/0.4.1/HarmonyRemote-Mac-0.4.1.zip) 与 [历史 Host HAP](../artifacts/releases/0.4.1/HarmonyRemote-Host-0.4.1.hap) 不覆盖。
4. 首轮选择 **10 分钟调试**，点击 **Start LAN Capture**，手动允许共享整个主屏幕。此模式从首帧开始计时，600 秒自动结束，显示动态图案和开发面板。另一选项 **永久上线**使用时长值 0，隐藏动态图案和开发面板，无自动结束时间。两种 LAN 模式都不保存桌面录像；开发面板中单独启动的 10 秒本地编码探针才保存 H.264，它不通过 LAN 发送。
5. Mac 看到画面后点击 **启用键鼠控制**，然后点击画面取得焦点。窗口失焦、鼠标离开画面/进入黑边会释放按键；`⌘⇧Esc` 释放视频焦点。

配对完成不自动开始共享。Mac 接收/解码仍为 `0 / 0` 时，先核对 Host 是否点击 **Start LAN Capture** 并完成本次录屏授权；无需因此重启服务。`VIDEO_READY` 只表示通道已连接，`STREAMING` 也可能处于等待系统授权阶段，收到实际首帧后才可启用网络输入。重启服务会清除 Host 的允许开关，且 Stop Server 会撤销输入授权，需重新完成第 2 步。

首次启动默认 **永久上线**。`PersistentStorage` 仅通过 `hrdSessionMode` 保存模式选择，重启后应恢复该选择；不会恢复配对、系统授权或允许远程控制开关，也不会自动开始共享。验收时分别选择两种模式并重启检查记忆与面板显隐，重连仍按上述授权流程执行。

## 一轮功能检查

| 操作 | 必须观察的结果 |
| --- | --- |
| 调整 Mac 窗口宽高，在远端画面四角和中心移动鼠标 | 光标位置对应，黑边不会产生远端操作 |
| 左键选中桌面图标、右键打开菜单、中键（支持它的目标应用） | 目标桌面/应用实际响应 |
| 拖动普通窗口、拖选文本，并单独复测文件拖动 | 按下、移动、抬起连续，松手立即停止；窗口和文字已由用户确认，文件仍待复测 |
| 浏览器或设置页面使用滚轮/触控板 | 上下及左右方向合理，惯性滚动离开窗口后停止 |
| 英文输入状态在备忘录空白文本中输入 `hello harmony 123` | 字符完整，无重复/丢失；Backspace/Enter/方向键正常 |
| Mac Friendly 模式 `⌘L`、`⌘A`、`⌘C/⌘V` | 鸿蒙接收 Ctrl 组合键，Mac 本地剪贴板不跨设备同步 |
| Shift、Ctrl、Option、Caps Lock及两侧修饰键 | 状态正常，松手后不残留；切换模式后须重新点击画面 |
| 按住 Shift 或鼠标后切换到 Mac 其他窗口/点击本地 IP 字段 | 鸿蒙按键释放，本地输入不转发 |
| 关闭远程控制或撤销系统授权 | 远端停止接收输入；再次开启须得到 Host 允许 |
| Mac 点击断开、Host停止共享、断开网络 | 释放按键和鼠标，视频停止，无后台继续控制 |

默认只捕获前台视频区域的输入，不申请 macOS Accessibility，不拦截 Cmd+Tab、Cmd+Space、Ctrl+方向等系统快捷键。Caps Lock 是按键事件转发，不保证首次连接时两端锁定状态相同；文本效果取决于鸿蒙当前键盘布局及输入法。密码区域和输入法浮窗的显示受系统隐私策略约束。

## 十分钟与永久模式

先完成 **10 分钟调试**整轮检查：在首帧前等待授权，记录首帧时间，确认约 600 秒后自动结束、EOS 完整、两端帧数可对应且没有新增 LAN 录像。提前停止的会话单独记录，不能当成完整十分钟通过。

完成基本输入检查后，重启服务生成新 PIN，再选择 **永久上线**。它不设固定结束时间；先进行覆盖旧 32 分钟边界的实机持续检查，再记录更长的实际时长。监测两端进程与内存基线，间歇滚动和输入；检查无崩溃、无累积延迟、无卡键，内存增长目标小于 100 MB。结束时记录主动停止或断线的实际原因；任何有限时长测试都只证明该次观测范围，不证明无限运行稳定。

0.5.0 Mac 等待首个有效非空 AU 仍有 **32 分钟**期限，过期等待不能被迟到首帧恢复；收到有效首 AU 后不再设置固定总时长，也不设累计 2 GiB 接收上限。每 2 秒心跳、6 秒失联结束、2 秒组包、8 MiB AU / 256 KiB CONFIG、有限队列及解码在飞限制仍保留。取消会话总量限制不会预分配或缓存整场视频，本地开发回放仍限 **64 MiB**。两种 LAN 模式均不持续写 H.264；独立 10 秒编码探针仍限 64 MiB，旧诊断视频不作为长会话录像。

0.4.1 的首 AU 前后各 32 分钟期限、累计 2 GiB 上限和开发测试是历史行为，证据见 [0.4.1 构建记录](../artifacts/build-verification-0.4.1.json)。0.5.0 本机测试已覆盖移除活动期限和累计上限，但**真实十分钟完整共享、永久模式长期运行仍未验收**。

**停止共享** 会排空编码 EOS；**Stop Server** 是立即断开服务，接收端可能报告未完整结束。两者都会先关闭远程输入并释放按键。

## 导出

Host 的 **保存当前诊断到应用目录** 会保存网络、编码和远程输入计数。开发机可运行：

```bash
python3 scripts/collect-lan.py --target 192.168.31.130:35029 --label control-take-01-host
```

使用新的 label，避免覆盖旧证据。Mac 右下角按钮可导出本次统计；`--diagnostics` 也能自动保存（若已有目标文件，则另建会话文件）。诊断不记录 PIN、token、输入文本或具体键序列。`acceptedEvents` 只表示队列接收，`processedEvents` 只表示注入 API 流程成功；必须与用户看到的目标应用效果一起判断。

释放检查须同时核对 `queuedEvents=0`、`busy=false`、三个 pending 计数为 0 和 `lastReleaseCode=0`；`inputReleases` 只是调用次数，不保证释放成功。输入计数为进程累计值，应记录动作前后差值。没有实际持有按键或鼠标时的清理结果，不作为持有状态释放的验收。

端到端 mouse-to-photon 延迟仍须独立测量，编码回调时间戳和 ping RTT 都不能代替该指标。
