# 资源使用检查与空闲修复（2026-10-04）

用户报告资源占用较高并关闭了软件。本轮保持应用关闭，只做源码检查、构建和无窗口测试；没有获得修复前后的实际 CPU、内存或能耗曲线，因此不能认定已解决全部高占用问题。

## 本轮修改

- Mac 显示层原来在未连接、断开和没有新帧时仍每秒运行 30 次计时器。现在由 `FrameMailbox` 从空变为有帧时通知显示层，最多安排一个一次性计时器，消费后没有新帧就不再唤醒。连续视频仍限制为最多 30 次显示提交/秒，保留最新一帧和替换计数。
- 替换会话、停止或销毁显示视图时，解除旧帧通知并取消等待中的显示。收到旧会话已排队的通知时会检查 mailbox 身份。
- 使用 `AVSampleBufferDisplayLayer.status` 的 KVO 捕获最后一帧之后的异步失败，错误保留在显示诊断中。Apple 本机 SDK 的 `AVSampleBufferDisplayLayer.h` 明确该属性支持 KVO。
- Mac 统计计时器仅在会话期间运行，完成或断开时停止，并保留完成后的最后一次统计刷新；状态值未变化时不再重复发布 UI 更新。剪贴板轮询仅在已连接、允许且方向包含 Mac 发送时运行。

验证：`bash scripts/test-mac-presentation.sh` 的 13 项检查通过，覆盖空闲无计时器、突发合并、速率限制、消费后停止、取消、销毁、最新帧替换计数、观察者解除和已有帧订阅。测试不创建应用窗口、不录屏、不操作系统剪贴板。日志：`artifacts/mac-presentation-tests-0.5.0.log`（本地产物，不纳入 Git）。实际窗口前后台切换、持续视频显示和性能改善幅度仍需下一轮实机复测。

## 已确认但本轮未改动的成本

| 项目 | 源码 / 构建证据 | 边界 |
| --- | --- | --- |
