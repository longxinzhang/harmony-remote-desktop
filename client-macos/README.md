# Harmony Remote macOS Viewer

原生局域网查看、键鼠、纯文字剪贴板与系统声音接收客户端：SwiftUI/AppKit 窗口、Network.framework 局域网连接、VideoToolbox H.264 解码，以及只保留最新已解码图像的显示路径。当前开发候选为 **`v0.6.0-rc.1`（产品版本 0.6.0，Mac `8`，配套 Host `1000011`）**。每次连接及恢复默认仅查看，在 Host 授权并允许之后可在 Mac 启用键鼠控制。Host 仍提供“10 分钟调试”和“永久上线”两种 LAN 共享模式，两者都不录像。

本轮已实现自动重连、记住设备、Mac 登录启动、远端 30/60 FPS 选项、Harmony → Mac 系统声音与网络统计。完整 Mac/HAP 最终构建、签名与编译源指纹核对已通过，候选包已归档；本轮锁屏且鸿蒙离线，尚未安装或进行真机验收，见[本轮记录](../docs/V0_6_0_ACCEPTANCE.md)。配对不等于传输加密；当前仍为可信局域网明文协议，首次 PIN 连接为首次信任设备公钥（TOFU），后续身份校验拒绝静默替换。录屏、输入和剪贴板系统权限仍须鸿蒙本机确认。

## 页面入口

- **远程桌面**：地址与配对码连接卡、记住设备及已配对设备入口；会话中显示画面，以及键鼠控制、剪贴板、静音和断开/取消重连操作。结束后保留最后一帧，可点击**返回连接**。
- **设置**：键盘与剪贴板、自动重连、移除配对、声音、登录 Mac 后启动及实际系统状态。
- **开发测试**：完整连接状态、接收/显示/解码计数、网络 RTT 与抖动、视频速率、声音及输入/剪贴板状态、**导出诊断**和本地回放说明。

切页不会断开会话或自动更改设置。离开远程桌面页会释放键鼠与待处理粘贴，暂停隐藏视图的显示调度；网络连接与解码继续，返回后点击画面才能再次操作。开发测试入口独立于鸿蒙的共享时长模式。完整行为见[工作区说明](../docs/UI_WORKSPACE.md)。

## 实时局域网查看

1. 测试时应使用配套候选构建（Host `1000011` / Mac `8`），先核对实际安装版本。鸿蒙端在**远程桌面**页点击**开启服务**，读取 RFC1918 IPv4 和一次性 6 位 PIN；“在线，等待连接”对应 `LISTENING`。双方处于同一可信局域网。
2. 在 Mac 的**远程桌面**页输入设备地址和配对码，点击**连接设备**。PIN 使用隐藏输入框，提交后清空；不要把 PIN 或 session token 放入启动参数、环境变量或日志。
3. 在 Host 的**设置 → 会话模式**选择**10 分钟调试**或**永久上线**；在**画面与声音**选择 30/60 FPS 以及是否共享系统声音。停止当前共享后才能调整，下一次共享生效。返回**远程桌面**，视频通道就绪后点击**开始共享屏幕**，在系统弹窗授权。调试从首帧起计时 600 秒；永久模式无自动结束时间。配对不会自动发起录屏，60 FPS 选项也不保证实际到达 60 FPS。
4. Mac 窗口显示收到的桌面，默认仅查看。Host 完成**授权键鼠权限**并点击**允许远程控制**后，可在 Mac 点击启用键鼠控制并点击画面操作。主动**断开**结束本次连接和共享，保留最后一帧；以后可使用已保存配对重新连接。未保存设备时使用 Host 当前显示的新 PIN，过期时重新开启服务获取。

可在开发启动时预填地址，并选择一个尚不存在的诊断文件：

```bash
open -n client-macos/build/HarmonyRemote.app --args \
  --host 192.168.31.130 \
  --diagnostics "$PWD/artifacts/mac-live-new.json"
```

Host 默认“永久上线”，持久偏好保存模式、帧率、声音及应用启动后监听选项；系统授权、远程控制允许状态和会话 token 不随偏好恢复。身份记录单独通过平台密钥存储处理。**开发测试**页在两种模式下均可进入；调试 LAN 编码中的动态图案仅在该页可见时运行，永久 LAN 共享不启用测试动画，两者均不保存 H.264。意外断线最多为同一认证设备保留原采集 60 秒；主动停止、关闭应用、原采集结束或保留期届满都会结束共享。

`--host` 仅预填地址，不自动连接。地址可保存在本机 `UserDefaults` 中；PIN/token 只用于内存中的当前配对会话，不写入诊断。控制/视频端口为 39871/39872，协商后的剪贴板独立使用 39873，系统声音使用 39874。协议校验包括配对、心跳、完整组包、序号、CONFIG/IDR 和 EOS。目前仍为可信局域网明文传输，签名配对不等于传输加密。

## 配对、恢复与启动设置

首次要记住设备时，Host 在**设置 → 持久配对**允许新增可信设备，Mac 勾选**记住这台设备**后使用 PIN 连接。Mac 将客户端私钥和 Host 公钥保存在系统登录钥匙串，Host 使用 HUKS 密钥及签名公钥名单；临时模式仅保留本次进程/服务内的恢复身份。以后从**已配对设备**连接无需再次输入 PIN，仍须 Host 正在监听及本机授权共享。更新 ad-hoc 签名构建可能出现系统钥匙串访问提示，需用户处理；持久化、重启与撤销的真实设备检查尚未完成。

**设置 → 连接与配对**中的自动重连仅重试已有认证身份的传输故障，间隔上限 30 秒。身份不符、协议或授权错误不会反复重试。等待期间可取消；重新连接不发送断线前排队的按键或粘贴，也不自动启用远程控制。超过 Host 保留期后，恢复连接仍需重新开始共享。

**设置 → 启动**可设置登录当前 Mac 用户后启动，并显示待批准等真实系统状态。安装或打开应用不会自动修改登录项。鸿蒙端只查询系统开机自启状态，可另外记住「打开应用后自动开启服务」；这一设置只在应用已经运行后监听，不是系统开机启动。见[启动能力边界](../docs/STARTUP.md)。

共享声音默认关闭，只接收鸿蒙系统内播放声音，不采集麦克风、不保存声音文件。Mac 可静音；当前没有两端时钟校准的声画同步。网络面板的 RTT 是控制通道往返时间，抖动取有效 RTT 的变化；视频 Mbps、接收 FPS 不代表最终显示帧率。真实听感、60 FPS、端到端交互延迟与资源占用须另行实测。

## 纯文字剪贴板

四种模式为 **关闭 / Mac → 鸿蒙 / 鸿蒙 → Mac / 双向**。首次默认关闭，Mac 保存方向偏好；Host 另有本地允许开关。开启、重连及切换方向都只同步之后的新复制，不自动交换原有内容；显式粘贴也不能发送开启前未重新复制的旧 Mac 内容，须重新复制或收到远端更新。单次最多 **1 MiB UTF-8 纯文字**，不保留排版；文件传输、文件粘贴与图片后续实现。

配对后，在 Host 点击 **允许读取剪贴板**并确认显示已允许（鸿蒙 → Mac 所需，已有授权时可能没有新弹窗），再点击 **允许剪贴板同步**，在 Mac 的**设置 → 文字剪贴板**选择方向并重新复制文字，会话工具栏也提供剪贴板菜单。Mac 如要求剪贴板访问许可，按系统提示确认；**复制远端文字到本机**可显式拉取当前远端文本。普通同步不需要启用键鼠。

远端粘贴还需 Host 输入授权、双方启用远程控制并聚焦共享画面。Mac → 鸿蒙开启时，`⌘V` / `Ctrl+V` 对新的 Mac 内容等待实际写入确认，已同步且未变化的内容则复用原事件，由 Host 核对当前剪贴板版本后粘贴。`⌘C` / `Ctrl+C` 及剪切按远程快捷键发送，并记录复制意图；没有收到这次远程复制的新内容时，不把未变化的旧 Mac 剪贴板作为新复制写回。失败、超时、失焦或内容变化时取消，不回落发送 raw V。鸿蒙 → Mac 接收可在 Viewer 不活跃时继续；完整后台场景和新版备忘录行为仍待真机复测。

见[剪贴板协议](../docs/CLIPBOARD_WIRE.md)、[平台权限](../docs/PLATFORM_CAPABILITIES.md)及[验证结果与边界](../docs/CLIPBOARD_TEST_RESULTS.md)。诊断只保存计数、字节数和错误，不保存文字、文字摘要或绑定凭据。

## 离线开发回放

回放输入为带 HRD1 包头的 `.hrd` 文件，不能直接把裸 `.h264` 传给 `--replay`。可将已经采集的真实视频封装为开发回放：

```bash
python3 scripts/make-mac-replay.py \
  artifacts/device/lan-take-01/capture.h264 \
  artifacts/mac-replay/lan-take-01-new.hrd \
  --expected-frames 287

open -n client-macos/build/HarmonyRemote.app --args \
  --replay "$PWD/artifacts/mac-replay/lan-take-01-new.hrd" \
  --diagnostics "$PWD/artifacts/mac-replay/lan-take-01-new-viewer.json"
```

封装工具使用开发机现有的 `ffprobe` 定位访问单元，校验与源文件的对应关系，并拒绝覆盖已有回放文件。它使用明确标注的 **合成 30 Hz 时间戳**；不推断真实采集帧率、原始 PTS 单位或网络延迟。画面在回放模式持续标明“本地回放 · 非实时”，开发测试页也显示回放状态。本地回放仍有 **64 MiB** 上限；它只验证本地协议解析、解码和显示，不连接 Host，不构成实时 LAN 证据。

独立解码开发检查入口为：

```bash
bash scripts/test-mac-decoder.sh
```

该脚本使用归档视频构造临时回放并运行解码测试；它不代替整个 GUI 的构建、画面检查或 live 验收。使用其他源视频时，封装命令中的 `--expected-frames` 应与该批实际帧数一致。

## 诊断与验收边界

在侧边栏**开发测试 → 会话诊断**点击**导出诊断**；`--diagnostics` 在会话完成后自动写入指定路径；已有文件不会覆盖，后续会话另建带会话 ID 的文件。诊断区分 `local_replay` 与 `live_lan`，记录接收/解码帧数、显示提交次数、已解码帧替换次数、尺寸、硬解查询结果和显示错误，不包含 PIN/token。

接收的压缩帧按序交给串行解码队列，VideoToolbox 回调将已解码图像放入单槽 mailbox；界面可以替换尚未显示的旧图像，不随意丢弃 H.264 参考帧。显示提交次数不等于物理屏幕实际刷新次数。`LOCAL_REPLAY_DECODED` / `LIVE_STREAM_DECODED` 表示相应解码会话结果，仍需检查显示错误和实际画面，不能单凭该字段认定 GUI 显示全部通过。

后续每次 GUI live 验收应分别记录 Host 授权、真实连接、接收/解码计数、硬解属性、桌面画面及断开行为。原始 PTS 单位未确认，线上时间戳来自编码输出回调单调时钟；此版本不测端到端延迟。0.4.1 修复后的窗口/文字拖拽已有实机确认，完整输入矩阵仍按 [验收步骤](../docs/REMOTE_CONTROL_ACCEPTANCE.md) 继续检查。

0.5.0 从连接开始等待首个有效非空 AU 仍有 **32 分钟**期限，迟到首 AU 不能恢复已过期的会话；有效首 AU 到达后取消固定总时长和累计字节上限。CONFIG、keepalive、空 EOS 不算首 AU。心跳仍每 2 秒发送、6 秒失联结束当前连接，再由重连策略决定是否恢复；首字节到完整消息/包的组装仍限 2 秒，单个 AU 限 8 MiB、CONFIG 限 256 KiB，输入/发送队列及解码在飞限制保留。取消累计上限不意味着将整个会话缓存到内存，见 [协议](../docs/PROTOCOL.md)。

**永久模式长期运行仍待真机验收**。0.4.1 曾对首 AU 前后分别设置 32 分钟期限并保留累计 2 GiB 上限，那是历史版本的行为；0.4.0 的约 24 分钟用户主动停止记录也不构成长会话完成证据。现有内存采样没有完整会话基线。当前仅用于可信局域网，TLS 属于后续版本。
